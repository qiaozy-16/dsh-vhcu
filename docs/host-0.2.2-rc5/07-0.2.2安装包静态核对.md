## 4. 对 dsh-vhcu 的直接含义

1. **P0 仍为 0**：安装包内 `dsh-tools` 的注册/执行契约与 npm 产物一致；`tools` 行 + native executor 由 base 默认提供。
2. **部署前置条件已由官方默认满足**：base 已挂 `tool-executor-native`；web-app 已删 `tools.mode`。只有当用户自定义 patch 覆盖 `tools` 时才需要再查。
3. **`dsh.plugin.json.compatibility.dshReleases` 确认不是闸门**：桌面壳 app-boot 里 0 命中。补 `0.2.2-rc.5` 只是声明性一致，不改变装载结果。
4. **CUA 风险降级为“可能未启用”**：包在，但没有默认挂载证据；仍需在影子启动/真实升级后看工具列表是否出现 `cua_*`。若出现，按 `05` 的 P2 处理输入争用。
5. **betterSidebar 仍是唯一外部 UI 变量**：它不在安装包内，0.2.2 不会替用户升级它；影子测试必须带当前 0.28.0 跑一次。

### 隔离启动预案（尚未执行）

0.2.2 桌面壳支持两个隔离点（实读 `lib/main.js`）：

- `DSH_HOME`：决定 `.dsh` 根（profiles / sessions / storage）；
- Electron `userData`：`app.getPath("userData")`，位于 `%APPDATA%\@deepseek-ai\dsh-desktop`。

建议影子启动时同时设置：

```
DSH_HOME=<workspace>/.tmp/dsh022-home
APPDATA=<workspace>/.tmp/dsh022-appdata
LOCALAPPDATA=<workspace>/.tmp/dsh022-localappdata
```

再从 `.tmp/dsh-022rc5/app/DeepSeek Harness.exe` 启动。这样不会读写真实
`C:\Users\mate\.dsh` 与 `%APPDATA%` 下的 0.2.1 数据。影子 profile 需要单独准备
（至少 `dsh-base` + `dsh-web-app` + `dsh-vhcu` + `dsh-better-sidebar`），
不能用真实 profile 直接指过去，避免插件管理写回真实组合。
