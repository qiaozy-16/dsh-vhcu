2. 本轮交付物
====================================================================
2.1 录制引擎（host/lib/recorder.js）
    纯 JS，不依赖原生模块，可单测。
    输入归一化事件：keydown / mousedown / wheel。
    输出步骤：
      {op:"click",x,y}
      {op:"right_click",x,y}
      {op:"scroll",amount}
      {op:"key",keys:["ctrl","c"]}
      {op:"type",text:"..."}
      {op:"wait",ms:N}
    规则：
      - 可打印键（字母/数字/标点/空格/小键盘字符）合并为 type；
      - 特殊键/快捷键转 key（映射 enter/tab/esc/space/backspace/delete/
        arrows/home/end/pageup/pagedown/f1-f12/ctrl/shift/alt/win）；
      - 鼠标左键 click、右键 right_click；中键/横向滚轮忽略；
      - 垂直滚轮 scroll（rotation 符号决定正负，amount 为幅度）；
      - 上一个动作到当前动作 >500ms，自动插入 wait；
      - 最多 50 步，超出 truncated=true；
      - CapsLock/NumLock/纯修饰键按下忽略；
      - 不支持键忽略并计数；
      - 关闭/停止时 flush 未落盘的 type。
    时长：从 start 到 stop；返回 step_count/event_count/ignored/truncated/duration_ms。
2.2 Node 集成
    懒加载：
      插件挂载时不 import uiohook；首次 start 才 import('uiohook-napi')。
      加载失败/Defender 拦截 → E_UNAVAILABLE + npm install/Defender 提示。
    依赖：
      uiohook-napi 从 devDependencies 移到 optionalDependencies：
      正常安装会带；安装失败不阻断插件，录制时优雅降级。
    函数：
      startMacroRecording()
        - E_BUSY 防重复；
        - 注册 keydown/mousedown/wheel；
        - uIOhook.start()；
        - state.recording={active:true,startedAt,eventCount,...}；
        - [A] 记录“⏺ 开始录制宏”。
      stopMacroRecording()
        - uIOhook.stop() + removeListener；
        - recorder.stop() flush；
        - state.recording.active=false；
        - 返回 steps/step_count/event_count/truncated/duration_ms；
        - [A] 记录“⏹ 停止录制（N 步）”。
    路由：
      POST /vhcu/recording {action:"start"|"stop"}
      same-origin + x-vhcu + JSON。
    工具：
      vhcu_start_recording
      vhcu_stop_recording
      （工具数 21 → 23）
    安全联动：
      - 紧急制动 doEmergencyStop 先 stopMacroRecording；
      - 插件 cleanup 停止原生钩子；
      - 进程退出/插件卸载不残留钩子。
2.3 UI（[A] Action）
    - 列表顶部录制条：
        ⏺ 开始录制宏  /  ⏹ 停止并保存
      说明“最多 50 步，间隔 >500ms 加 wait”。
    - 录制期间所有标签顶部常驻红条：
        ⏺ 正在录制中，请操作屏幕  点击右侧停止并保存
      右侧按钮“停止并保存”。
    - 停止流程：
        POST /vhcu/recording stop
        → 无步骤：提示“没有捕获到步骤”
        → window.prompt 输入宏名（默认 macro_recorded_<timestamp>）
        → POST /vhcu/macros {action:"save"}，category=我的自定义宏
        → 刷新宏列表。
    - 取消命名：提示“录制已停止，未保存”。
    - 保存失败：显示 Node 返回的 error/hint。

4. 风险与未验证项
====================================================================
R1. 录制使用绝对屏幕坐标；窗口位置/分辨率/DPI 改变后重放可能点错。
R2. 文本转 type 基于 US 键盘布局；非 US 布局/输入法下字符可能不一致。
R3. CapsLock 状态未跟踪；大写只按 shift 判断。
R4. 只监听 keydown；按键重复、组合键 keyup 不做特殊处理。
R5. 中键、横向滚轮、部分媒体键忽略。
R6. 50 步截断是硬上限；长操作录制会丢后续步骤。
R7. 录制会看到所有应用的键盘输入（包括密码），
    目前只有 UI 提示，没有自动隐私过滤。
R8. 停止后 window.prompt 取消会丢弃本次录制。
R9. 原生钩子被 Defender/EDR 拦截时录制不可用；
    optionalDependency 缺失时同样降级。
R10. 未改 Python；录制不涉及 Python。

5. 待确认决策（编号）

D6. 录制期间不禁用系统输入，也不 suppress 事件。
