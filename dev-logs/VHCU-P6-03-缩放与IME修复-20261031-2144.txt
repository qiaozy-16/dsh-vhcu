1. max_width 缩放 Bug
====================================================================
1.1 复现
  vhcu_get_full_frame(max_width=1600) → frame_url 正确带 maxw=1600，
  但下载的 PNG 是 960x540（正好 1920x1080 的一半）。
1.2 根因（vision/vhcu_daemon/httpframe.py render_png）
  旧实现：
    step = max(1, ceil(w / max_width))     # 1920/1600 → 2
    out_w = len(range(0, w, step))          # 960
    out_h = len(range(0, h, step))          # 540
  整数步长只能产生 1/k 缩放；step=2 就“砍半”，与 max_width 的期望无关。
  另外旧实现对裁剪区域也按同一 step 抽样，尺寸不可控。
1.3 修复
  out_w = min(w, max_width)
  out_h = max(1, (h * out_w + w // 2) // w)   # 按宽高比四舍五入
  src_xs[i] = min(w-1, i*w//out_w)
  src_ys[j] = min(h-1, j*h//out_h)
  逐行按映射采样（最近邻），再 encode_png。
  - 1920x1080, max_width=1600 → (1600, 900)
  - 320x180, max_width=2000 → (320, 180)（不放大）
  - 100x50, max_width=25 → 25x13（原有测试语义保持）
1.4 性能与超时
  纯 Python 1600x900 采样+编码约 0.5s（实测全链路 815ms）。
  Node /vhcu/frame 的 fetchFrame 超时从默认 2s 提升到 5s，避免大图偶发超时。
  仍受 MAX_DIMENSION 8192 与 8MiB 响应上限约束。

2. 中文 IME 乱序保护
====================================================================
2.1 现象
  中文输入法开启时，逐字符 KEYEVENTF_UNICODE 注入会被 IME 重新组合成候选串，
  出现乱序/丢字；用户实测只能 Ctrl+Z 撤销后改英文。
2.2 保护策略（input.py）
  - 新增 ime_open_status()：
      GetForegroundWindow → ImmGetContext → ImmGetOpenStatus；
      只读查询，异常/无 imm32 返回 None，绝不抛错。
  - type_text 注入前：
      ime_open = ime_open_status()
      if ime_open: 发送一次 Shift 切换中英（_tap_vk(SHIFT)），sleep 0.08
      然后再逐字符注入；
      返回 {chars, imeOpen, imeToggled}。
  - dry-run 返回 imeOpen=None、imeToggled=False（不触碰真实 IME）。
  - 局限：Shift 切换依赖输入法配置（微软拼音默认支持）；少数 IME 用 Ctrl+Space。
2.3 模型侧兜底（lib/index.js Description）
  追加：
    「若输入中文出现乱序/候选框未上屏，请提醒用户切换到英文输入法（或先用
      vhcu_key_press(["ctrl","z"]) 撤销再重试）；本工具在检测到输入法开启时会先
      按 Shift 尝试切英文。」
  Node 返回体新增 ime_open / ime_toggled，并在 message 中标注是否切过英文。
