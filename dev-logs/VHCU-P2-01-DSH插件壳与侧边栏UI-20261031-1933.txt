2. 插件结构（DSH 如何识别）
====================================================================
2.1 package.json 关键字段
  "main": "./lib/index.js"
  "exports": { ".": "./lib/index.js", "./client": "./lib/client.js", ... }
  "dsh": {
     "manifestVersion": 1,
     "bundle": { "patch": "./cordis.patch.yml" },
     "client": { "platform": "web", "inject": [] }
  }
  "engines": { "node": ">=20", "dsh": ">=0.1.5-rc.1 <0.3.0-0" }

2.2 dsh.plugin.json
  entry.name = dsh-vhcu，entry.inject = ["webServer"]
  client.platform = "web"，client.inject = []
  （真正的 sidebar 服务依赖由 lib/client.js 的模块级 inject=["betterSidebar"] 声明，
   避免把服务名误当 npm 包名。）

2.3 cordis.patch.yml
  - insert:
      - id: vhcu
        name: 'dsh-vhcu'
  只增量插入，不替换/禁用任何核心行。

2.4 挂载后宿主侧行为
  apply(ctx) 只做三件事：
   ① 注册 4 条路由（ctx.effect 包装）；
   ② 注册清理钩子（ctx.effect + ctx.on('dispose')）；
   ③ 打一行日志：dsh-vhcu: mounted (routes ...)。
  **挂载本身不 spawn Python**（D4 按需唤醒）：只有 UI 点「开启视觉」才走 control.start。

3. 路由与数据格式（P2 实测）
====================================================================
GET /vhcu/state
  → { ok, state:{ phase, running, pid, port, source, fps, startedAt, lastError,
                  python, counters:{frames,diffs,errors}, clients, lastEventId },
       events:[最近 100 条] }

GET /vhcu/events（SSE）
  首帧：event: hello  data:{state, events:[最近100]}
  状态：event: status data:{快照}
  事件：event: event  data:{id, ts, kind, text, level, ...}
  心跳：每 15s 一行 ": vhcu hb <ts>"
  断线：retry: 2000；带 Last-Event-ID 时补发环里更大的 id
  上限：4 个并发 SSE 客户端（超出 429）

POST /vhcu/control
  头：content-type: application/json + x-vhcu: 1
  body：{action:"start"|"stop"|"restart"|"ping"|"status"}
  串行化：内部 queue，避免双击/并发 start 产生两个 daemon。
  返回：{ok:true,state} 或 {ok:false,error:{code,message,hint},state}

GET /vhcu/frame?x=&y=&w=&h=&maxw=
  → image/png（代理 Python 图像面；token 留在宿主侧）
  当前极简 UI 未用（下一步美化时加缩略图）。

安全：
  - 同源校验：Origin 与 Host 不一致 → 403；
  - 控制路由额外要求 x-vhcu: 1（跨站表单无法构造自定义头）；
  - SSE/控制 GET 不返回 ACAO，跨源脚本读不到内容；
  - 路由随插件卸载自动解绑，SSE 全部 end，supervisor.stop()。

4. 侧边栏 UI（极简版）
====================================================================
lib/client.js 是手写模块，形态与官方发布产物一致：
  window.__ModuleLoader__.load({ id:'dsh-vhcu', factory:(require)=>{ ... return module.exports; } })
  module.exports = { name:'dsh-vhcu', inject:['betterSidebar'], apply(ctx) }

apply(ctx) → ctx.effect(() => ctx.betterSidebar.registerTab({
  id:'vhcu:monitor', title:'VHCU 视觉',
  description:'按需视觉监控：启停、状态灯与实时差分事件流',
  order:120, single:true, component:()=>React.createElement(Panel)
}))

Panel 只用 4 个 hook（useState/useEffect/useRef/useCallback）：
  - 挂载：GET /vhcu/state 取初值；new EventSource('/vhcu/events') 订阅；
  - 事件：hello/status 覆盖状态，event 前插并去重（最多 200 条）；
  - 按钮：POST /vhcu/control，请求期间禁用，失败显示 hint；
  - 状态灯：idle 灰 / starting 黄 / running 绿 / stopping 黄 / error 红；
  - 列表行：HH:MM:SS + 文案（示例「检测到画面变化 · 7 个区域 · 4.67ms · 1920x1080」）。
  - 样式全部内联 + 一个 <style id="dsh-vhcu-style">，不污染宿主 CSS；
  - 未安装 dsh-better-sidebar 时 apply 静默返回，不拖垮客户端插件树。

6. 如何挂载与本地启动测试（照做即可）
====================================================================
6.1 已挂载，只差重启（本机当前状态）
  ① 完全退出 DSH 桌面应用（不是关窗口；托盘退出/任务管理器确认进程结束）。
  ② 重新打开 DSH。
  ③ 打开右侧栏，点「+」菜单，应出现 **VHCU 视觉**。
  ④ 点进去 → 点「开启视觉」→ 看到状态灯变绿、事件开始滚动。
  ⑤ 停止：点「关闭视觉」→ 灯变灰，任务管理器无 python.exe。

  宿主日志确认（DSH 日志目录）：
    dsh-vhcu: mounted (routes /vhcu/state|events|control|frame)

6.2 如果以后要从零挂到另一台机器
  cd dsh-vhcu
  node scripts/install.mjs --dry-run    # 先看三件事
  node scripts/install.mjs              # junction + 原子改 profile（自动 .bak）
  # 重启 DSH

6.3 回滚
  node scripts/install.mjs --uninstall  # 移除 junction/依赖/bundle 条目（保留 .bak）
  # 或只用备份恢复：copy package.json.bak package.json（注意会丢掉安装后的其它改动）

6.4 不重启也能验收后端 + 面板
  npm run dev
  # 浏览器打开 http://127.0.0.1:49380/dev
  # 同一个 host 插件、同一套 SSE；适合改 UI/排查生命周期

6.5 常见问题
  - 看不到 tab：确认 dsh-better-sidebar 已安装；确认 profile bundles 里有 dsh-vhcu；
    确认重启是「完全退出」；看宿主日志是否有 mounted 那一行。
  - 点开启报 E_UNAVAILABLE：mss 未装/不可用，插件会自动退 fake；看事件里的 hint。
  - 点开启报 E_STATE/E_TIMEOUT：daemon 卡住或上一次没退干净；点一次「关闭视觉」再开，
    或重启 DSH（dispose 会杀子进程）。
  - SSE 一直 retry：路由未注册（插件没加载）或被反向代理缓冲；先看 /vhcu/state 是否 200。

7. 已知边界与风险
====================================================================
R1. 客户端模块只在 vm 里验证了「模块形状 + 渲染树」，真实 DSH client loader 的加载
    需要重启后才能确认。风险点：exports["./client"] 解析、betterSidebar 服务就绪顺序。
    已按官方 dsh-unified-agent-memory 的产物形态逐字对齐（__ModuleLoader__ + module.exports）。
R2. tab 依赖 dsh-better-sidebar；缺失时静默跳过（不崩，但也没有入口）。
R3. 插件挂载后不 spawn；但一旦点过开启，Python 会常驻到点关闭或 DSH 退出（dispose 兜底）。
R4. 差分仍是粗网格采样，真实桌面有少量误报；UI 目前只展示文本，未做 ROI 缩略图。
R5. 没有单实例锁；不要在 profile 里重复挂同一个 bundle（route 注册会冲突）。
R6. 安装脚本会改 profile package.json；写入前已备份，写入用 tmp+rename 并重新解析自校验。
R7. 隐私：mss 抓的是整屏。当前只有本地 JSON 与本地 PNG，不出机器；开启按钮是显式动作。
