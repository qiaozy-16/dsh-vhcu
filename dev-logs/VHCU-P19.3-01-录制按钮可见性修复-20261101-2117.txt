范围：仅前端 lib/client.js 的录制入口位置/文案/状态反馈；不改 Node 录制引擎。

====================================================================
1. 时间 / 阶段 / 范围
====================================================================
  时间：2026-11-01 21:17 +08:00
  阶段：P19.3
  用户反馈：
    - 重启 DSH 后，[V]/[A]/⚙ 都找不到「🔴 开始录制宏」。
  排查结论：
    - 代码并非完全漏写：P19.2 确实在 [A] 列表顶部渲染了录制条；
    - 但按钮文案是「⏺ 开始录制宏」，不是用户寻找的「🔴」；
    - 且它位于可滚动 Action 列表内部，不够显眼，容易被当成普通条目。
  修复范围：
    - lib/client.js：
        录制按钮移到 meta 下方、Tabs 上方的常驻控制条；
        文案改为精确的「🔴 开始录制宏」；
        录制中变「⏹ 停止并保存」+ 红色实心/脉冲；
        状态文字常驻「正在录制中，请操作屏幕」。
    - 测试：client.test 增加渲染级断言（按钮在 Tabs 之前）。

      按钮：红色实心 + 脉冲动画（vhcu-pulse）
      整条：深红背景 + 红色下边框
      说明：正在录制中，请操作屏幕
    处理中：
      按钮：处理中…
    按钮 aria-pressed 跟随状态；状态条 role=status / aria-live=polite。

    → POST /vhcu/macros save（category=我的自定义宏）
    → 刷新宏列表。

4. 风险与未验证项
====================================================================
R1. 如果重启后仍看不到，可能是 DSH 加载了旧 client bundle 或旧窗口；
    需要完全退出 DSH（不是只关闭窗口）并确认无残留进程。
R2. 常驻控制条占据约 30px 高度；极窄侧栏下说明文字会截断，
    但红色按钮固定可见。
R3. 录制中按钮脉冲动画不影响点击。
R4. UI 只在 state.recording.active=true 时显示停止态；
    若后端启动失败，按钮保持「🔴 开始录制宏」并显示错误提示。
R5. 本轮只改 UI，不改变 P19.2 的录制数据/保存逻辑。
