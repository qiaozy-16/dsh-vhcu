2. 控制与生命周期（lib/index.js）
====================================================================
2.1 control 新 action
  hear.start：
    enqueue(doStartHear)
    → ensureDaemonReady()：如果 supervisor 不存在/未 ready，则启动 Python
      守护进程（只 ready，不发送 vision.start）；
    → supervisor.send("hear.start")；
    → state.hear 更新，pushStatus。
  hear.stop：
    enqueue(doStopHear)
    → 若守护进程 ready，send("hear.stop")；
    → state.hear=idle；
    → 若 state.phase !== "running"（视觉没开）：supervisor.stop("hear-stop")，
      daemonRunning=false，pid/port 清空；
    → pushStatus。
  hear.status：
    守护进程未运行 → 返回当前 state.hear；
    否则 send("hear.status") 返回并附在 snapshot。
2.2 状态
  state.daemonRunning: boolean（Python 守护进程是否存活）
  state.hear: {state,running,model,device,computeType,modelPath,segments,lastError}
  - doStart（视觉）置 daemonRunning=true；
  - doStop（视觉）置 false、hear idle；
  - supervisor failure → daemonRunning=false、hear state=error。
2.3 失败清理
  hear.start 失败（如 E_UNAVAILABLE）且视觉没开时：
    停止刚拉起的守护进程，避免留下空转 Python；state.hear=error，UI 可重试。
2.4 工具描述/行为
  vhcu_start_hear：不再要求 start_vision；描述明确“自动唤醒守护进程、
    只启动 Hear 线程、不截屏”。
  vhcu_stop_hear：若视觉没开，停止后守护进程退出；视觉开着则保留。
  工具仍通过 control 串行化，避免与视觉启停竞争。

4. 接口变化
====================================================================
  POST /vhcu/control
    {action:"hear.start"} → {ok:true,state:{...,hear,daemonRunning}}
    {action:"hear.stop"}  → 同上，hear.state=idle
    {action:"hear.status"}→ snapshot + hear
  GET /vhcu/state：新增 state.daemonRunning；state.hear 原有。
  SSE：hear.status 只用于状态点；hear.text 仍为数据事件。
  UI 按钮不直接调工具，统一走 /vhcu/control（符合 P12.2 要求）。

5. 重启验证
====================================================================
5.1 安装依赖（若未装）
  py -3 -m pip install soundcard webrtcvad-wheels faster-whisper
5.2 重启
  完全退出 DSH（确认 Electron/python.exe 无残留）→ 重开 → 新会话。
  日志：
    dsh-vhcu: mounted (routes /vhcu/state|events|control|frame|settings|macros)
    dsh-vhcu: registered 16 tools
5.3 纯 Hear 验证（不要先开视觉）
  1) 打开侧边栏 VHCU → [H] Hear；
  2) 应看到控制条、灰色状态点、「开启听觉」；
  3) 点击「开启听觉」：
     - 状态点变黄，文案「模型加载中…」；
     - 首次下载 base 到 dsh-vhcu\models（约 150MB）；
     - 完成后变绿，「正在监听系统声音」；
  4) 播放系统外放音频 → 列表出现转写行 / vhcu_get_hear_events 有文本；
  5) 点击「关闭听觉」→ 灰点；任务管理器确认 Python 进程退出（因为视觉没开）。
5.4 视觉 + Hear
  1) 先「开启视觉」；
  2) Hear 开启/关闭只影响音频，视觉守护进程保留。
5.5 缺依赖
  未安装依赖时点按钮：应显示 E_UNAVAILABLE + pip hint，状态点变红，不卡死。
5.6 取消加载
  在模型下载中点击「取消加载」：按钮触发 hear.stop，UI 回 idle；
  实际线程可能因下载阻塞需数秒退出（已知边界）。

7. 已知边界与下一步
====================================================================
R1. Hear 仅 Windows WASAPI Loopback；模型 base/cpu/int8。
R2. 只开 Hear 时 phase 仍为 idle（视觉确实关闭），daemonRunning=true；
    这是故意区分“视觉状态”和“守护进程状态”。
R3. 模型下载期间取消加载可能需等下载 IO 退出（join 8s 超时后 UI 已回 idle）。
R4. 真实音频/模型下载未本机验证（依赖未安装）。
R5. 停止视觉仍会杀掉守护进程并停止 Hear（视觉与 Hear 共享进程）。
R6. 状态点是轮询/SSE 状态更新，非动画 loading 条。
