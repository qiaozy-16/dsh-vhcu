1. 任务一：过滤 ASR 幻听
====================================================================
1.1 hear.py imports
      re, unicodedata
1.2 常量
      _MEANINGLESS_TOKENS = {
        music, applause, laughter, hover, silence, noise, sound, speech,
        音乐, 掌声, 笑声, 静音, 噪音, 声音
      }
      _TAG_RE = \[...\] / (... ) / （...）/ 【...】
1.3 should_discard_transcript(text)
      - 空/空白 → True；
      - 单个 ASCII 字母（A/z）→ True；
      - 去掉 [Music] 等括号标签后：
          · 没有字母/数字 → True（纯标点/符号/♪）；
          · 所有 token 都在 meaningless 集合 → True；
      - 否则 False。
      示例：
        丢弃: "", "...", "!!!", "♪ ♫", "[Music]", "[Applause]",
              "Hover", "[Hover]", "Music", "音乐", "[Music] [Applause]"
        保留: "请打开设置", "打开音乐播放器", "Hover 请点击这里",
              "안녕하세요", "Hello world", "Open the settings"
      - 不按语言全局过滤，避免误删真实韩语/日语。
1.4 whisper 参数
      model.transcribe(
          audio,
          beam_size=1,
          vad_filter=False,
          condition_on_previous_text=False,
          no_speech_threshold=0.6,
          log_prob_threshold=-1.0,
      )
1.5 过滤位置
      text = 转写结果
      if should_discard_transcript(text):
          print("[hear] discarded hallucination: ...", stderr)
          return
      → 不更新 _last_text、不 emit、不进入融合层。
1.6 未做
      - 未增加“播放结束后延迟抓帧”或保存逻辑（按需求，属测试者关窗时序）。
      - 未对 whisper 模型或 VAD 参数做其它改动。

6. 已知边界
====================================================================
R1. 幻听过滤是规则式：真实语音里只念 “Music” 也会被丢；
    含正文的音乐标签会保留。
R2. target_app 是窗口标题子串匹配，不读取进程名；标题变化会影响推荐。
R3. vhcu_get_active_window 在守护进程未运行时临时启动/停止 Python，
    首次调用有 1-2s 延迟。
R4. target_app 最长 80 字符，不做正则/通配符。
R5. 真实前台窗口标题与宏推荐需重启后人工验证。
R6. 未为测试者“播放结束立即关窗”增加任何延迟——如实保持原时序。
