2. 本轮交付物
====================================================================
2.1 任务一：隐私黑屏与原地罚站
    Python runner.capture_now(allow_unprotected=False)：
      - 敏感窗口且未开高危：不抓取任何敏感像素；
      - 生成全屏黑 Frame（BGRA 全 0）；
      - 返回 privacyBlocked=true / masked=true / warning；
      - 绝不关闭、最小化、移动窗口，也不发送任何快捷键。
    Node captureFullFrame：
      - 敏感时返回 ok:true + 黑色 frame_url + warning：
        [系统提示：当前处于敏感隐私窗口。画面已打码，请立刻停止所有动作，
         原地等待用户自行切走该窗口。]
      - 同步 state.privacy.blocked=true；
      - masked 帧不会成为 click 坐标基线。
    Python 输入层：
      - state.privacy.blocked 时 Node 直接拒绝所有键鼠注入（E_STATE），
        AI 原地暂停。
    UI：
      - 常驻红黄横幅：
        🔒 隐私保护触发：AI 已暂停，请处理完毕后切换窗口
      - ⚙ 新增「允许无保护截屏（高危）」；
      - 勾选后出现二次确认（确认开启/Cancel），
        确认后仍需点「保存设置」才生效；
      - 高危仅放行截图，键鼠动作仍被隐私拦截。
2.2 任务二：焦点被抢占防护
    Python privacy.foreground_identity()：
      - 只读 GetForegroundWindow / GetWindowThreadProcessId / GetWindowText；
      - 返回 {hwnd,pid,title}。
    Runner：
      - vision.diff / vision.capture 附带 foreground 身份；
    Node：
      - 保存 lastForeground；
      - runInputAction 自动传入 expectedForeground；
    InputController.assert_foreground：
      - 注入前比较当前 hwnd；
      - 不同 → InputError E_FOCUS_LOST；
      - hint：
        ⚠️ 检测到前台窗口焦点已被用户改变，本次操作已被拦截。
        请重新调用 vhcu_get_full_frame 确认当前屏幕状态后再重试。
    CLI `_input()` 在 click/type/hotkey/scroll/drag/macro 前统一校验。
2.3 任务三：视觉时序校验
    `vhcu_mouse_click` 新增可选参数：
      frame_timestamp（epoch ms）
    vhcu_get_full_frame 返回 frame_timestamp。
    点击前：
      - 非法 → E_PROTO；
      - 距现在 >1000ms → E_STALE_FRAME；
      - hint 要求重新调用 vhcu_get_full_frame 取新图和新的时间戳。
    纯函数：host/lib/guards.js `isStaleFrame()`。
2.4 任务四：音频设备掉线重连
    hear.py `_capture_loop`：
      - recorder.record / 打开设备抛异常时不再让线程崩溃；
      - `_set("reconnecting")` + hear.status：
        message="音频设备断开，尝试重连中"；
      - 关闭旧 recorder，等待 1s，重新 `_open_loopback` + `mic.recorder`；
      - 成功后 status listening，message="音频设备已重新连接"；
      - 重连时清空当前语音缓冲，避免拼接旧音频。
    UI：
      - Hear 状态支持 reconnecting；
      - 文案：音频设备断开，重连中…
2.5 任务五：过滤调试开关
    ⚙ 新增「关闭幻觉过滤（输出原始转写）」；
    settings.hearRawTranscripts → Node hear.configure
      {level, disableFilter}；
    HearService.configure(level, disable_filter)；
    disableFilter=true 时跳过 classify_transcript，直接输出原始转写；
    status 返回 disableFilter。
2.6 任务六：资源防爆与宏限制
    内存：
      - host/lib/guards.js MEMORY_LIMIT_BYTES=1.5GB、MEMORY_CHECK_MS=5s；
      - Node 定时读取 process.memoryUsage().rss；
      - 超过水位且视觉运行 → note 警告、doStop 熔断视觉、
        state.phase=error、lastError.code=E_MEMORY；
      - UI 红色内存警告横幅。
    宏：
      - MAX_STEPS 50 → 30；
      - MacroRecorder 默认 30；
      - 前端导入校验 >30 拒绝；
      - 录制进度实时显示 N/30；
      - 达到 30 步：Action 日志警告 + 录制条警告；
      - 停止保存表单摘要标记“已达到 30 步上限”；
      - 旧 macros.json 中 31..50 步宏：加载时保留前 30 步并持久化，
        不再当损坏文件重置。
2.7 任务七：操作前视觉确认规范
    新增 VHCU_VISUAL_CONFIRM_RULE：
      如果对当前画面拿不准，在调用宏或连续点击前，
      必须先重新调用 vhcu_get_full_frame 确认画面；
      点击/按键后也要用 vhcu_get_vision_events 或 vhcu_get_full_frame 回读，
      确认无误再继续。
    应用于视觉/动作工具（start_vision、get_full_frame、get_vision_events、
    click/drag/scroll/key/type、run_macro、save_macro 等）。
2.8 暂不开发项

4. 风险与未验证项
====================================================================
R1. 隐私黑图警告文本在工具返回中，未把文字画进 PNG；
    图片本身为纯黑，模型需读取 message/warning。
R2. 焦点校验基于最近一次视觉帧的 foreground；
    宏内部主动切换窗口（如 Win+R）不会被逐步拦截，只在动作入口校验。
R3. frame_timestamp 只校验时间年龄，不校验它是否属于最后一帧；
    模型应使用 vhcu_get_full_frame 返回的新时间戳。
R4. 无保护截屏只放行截图；键鼠仍会被隐私暂停拦截。
R5. Hear 重连单测使用 fake recorder；真实 soundcard 设备异常行为未验证。
R6. 1.5GB 是 Node 宿主 RSS，不是 Python 进程内存；可能较早/较晚触发。
R7. 30 步上限会截断旧宏；迁移只保留前 30 步，不提供恢复。
R8. 旧宏迁移会写回文件；写入失败会落入既有损坏保护路径。
R9. 视觉确认规则是 Description 引导，不是运行时强制。
R10. 本轮未实现系统级“AI 正在操作电脑”告知 UI。
