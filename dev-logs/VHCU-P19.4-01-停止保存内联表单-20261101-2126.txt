2. 本轮交付物
====================================================================
2.1 停止流程
    旧：
      stop → window.prompt() → 保存 → 刷新
      （DSH Electron 直接报错，21 步数据无法命名）
    新：
      stop → 后端返回 steps
      → setPendingRecording({steps,step_count,event_count,duration_ms,truncated})
      → setMacroForm({name: macro_recorded_<timestamp>, category: 我的自定义宏})
      → 录制条下方内联展开保存表单
      → 用户编辑名称/分类
      → 确认保存 → POST /vhcu/macros {action:"save"} → 刷新宏列表
2.2 表单
    位置：recordStrip 下方、Tabs 上方（任何标签页可见）。
    内容：
      已捕获 N 步 · M 个输入事件 · X 秒
      宏名称 [默认 macro_recorded_<timestamp>]（自动聚焦）
      分类   [默认 我的自定义宏]
      [确认保存] [取消]
    行为：
      - Enter 提交（form onSubmit）；
      - 名称空 → 黄字“宏名称不能为空”，表单保留；
      - 保存中按钮“保存中…”，禁用重复提交；
      - 保存失败 → 显示 Node error/hint，表单与已录 steps 保留，可改后重试；
      - 成功 → 清空 pending、刷新宏列表、表单消失；
      - 取消 → 清空 pending，提示“已取消保存，本次录制未写入”。
    截断提示：
      truncated=true 时摘要追加“⚠ 已达到 50 步上限，后续动作被截断”。
2.3 状态保护
    - pendingRecording 存在时，录制条「开始录制宏」禁用，
      防止未保存数据被新录制覆盖；
    - 成功开始新录制会清空 pending；
    - 保存失败不清空 pending；
    - 不使用 window.prompt / alert / confirm。

4. 风险与未验证项
====================================================================
R1. 表单依赖 stop 接口成功返回 steps；若 stop 失败，保留录制状态并报错。
R2. 取消保存会丢弃本次录制（未写入 macros.json）。
R3. 表单使用受控 input；输入法组合期间 onChange 可能触发多次，但不会丢字。
R4. 自定义分类名超长/重复由 MacroStore 的 normalize 报错，表单保留可改。
R5. 本轮未改录制引擎；21 步转换逻辑仍沿用 P19.2。
R6. 若重启后仍看到旧 prompt 行为，说明加载的是旧 client bundle，
    需要完全退出 DSH 再重开。
