2.2 文字注入多级降级
    Python type_text(text, ime_shortcut, use_clipboard_fallback=False)：
      - 默认仍走 Unicode 注入；
      - use_clipboard_fallback=true 时：
        1. 读取并备份当前剪贴板文本；
        2. GlobalAlloc/GlobalLock/SetClipboardData 写入临时文本；
        3. 通过扫描码发送物理 Ctrl+V；
        4. 等待 120ms；
        5. finally 恢复原剪贴板文本；
      - dry-run 不触碰剪贴板，返回 clipboardFallback 标记；
      - 剪贴板被占用时重试 6 次，仍失败返回 E_CLIPBOARD；
      - 适配 Blender 等不接收 Unicode 注入的软件。
    CLI input.type：
      - 透传 useClipboardFallback。
    Node vhcu_type_text：
      - 新增 use_clipboard_fallback:boolean；
      - 返回 clipboard_fallback；
      - 文案区分“已输入”与“已通过临时剪贴板粘贴”。
2.3 组合键扫描码与延迟
    Python key_press(keys, delay_ms=0)：
      - delay_ms 校验 0..1000；
      - 记录 delayMs/scancode 到 dry-run 与真实返回；
      - 组合键发送改为扫描码：
        MapVirtualKeyW(vk, 0) → wScan + KEYEVENTF_SCANCODE；
      - 有修饰键且 delay_ms>0：
        先发送所有修饰键 keydown；
        sleep(delay_ms)；
        再发送主键 down/up 与修饰键 up；
      - delay_ms=0 时一次性发送，保持低延迟。
    CLI input.hotkey：
      - 透传 delayMs。
    Node vhcu_key_press：
      - 新增 delay_ms（0..1000，默认 0）；
      - 透传 Python，返回 delay_ms；
      - 描述明确扫描码与 Shift+A 场景。

4. 风险与未验证项
====================================================================
R1. 剪贴板回退会暂时接管系统剪贴板；若恢复失败，用户剪贴板可能残留粘贴文本。
R2. 剪贴板被远程桌面/剪贴板管理器占用时可能 E_CLIPBOARD。
R3. 扫描码使用 MapVirtualKeyW；极少数布局/特殊键（媒体键、部分输入法键）
    可能仍无扫描码，此时 fallback 到 VK 发送。
R4. delay_ms 只插入修饰键→主键之间；主键→释放之间不加延迟。
R5. 折叠面板默认状态只在打开面板时生效；关闭面板不会持久化展开状态。
R6. 危险区仍保留二次确认，但改名后文案风险等级更明确。
R7. 真实 Windows 注入未在自动化测试中执行（测试为 dry-run）。
