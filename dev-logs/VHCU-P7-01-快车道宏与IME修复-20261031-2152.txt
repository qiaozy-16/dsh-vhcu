1. IME 修复（Ctrl+空格）
====================================================================
1.1 问题
  P6.2 用 Shift 切中英；用户系统实际是 Ctrl+空格。按 Shift 可能产生大写/乱码。
1.2 实现（input.py）
  - _ensure_ascii_input()：
      before = ime_open_status()
      若未开启 → (False, before, before)，不发送任何按键；
      若开启 → _send_combo([CTRL, SPACE]) → sleep 0.12 → 复查
                仍开启 → 再发一次 → sleep 0.12 → 复查
      return (True, before, after)
  - type_text：调用 _ensure_ascii_input() 后再逐字注入；
    返回 {chars, imeOpen, imeAfter, imeToggled}。
  - 宏内部在输入 "notepad" 前、输入正文前各调用一次（防止运行框/编辑器重置 IME 状态）。
  - _lock 改为 RLock，使宏可以复用 type_text/_send_combo 等原语而不死锁。
1.3 Node 侧
  - Description 由 Shift 改为「按 Ctrl+空格 切换英文（无效会再试一次）」。
  - 返回体增加 ime_open / ime_after / ime_toggled；message 标注是否切过英文。
  - 乱序兜底仍提示用户切英文，或先 vhcu_key_press(["ctrl","z"]) 撤销。

2. 快车道宏
====================================================================
2.1 Python（input.py）
  macro_open_notepad_and_type(text):
    rate_limit + failsafe
    dry_run → {dryRun:true, steps:[win+r, type:notepad, enter, wait:1000, type:text], elapsedMs:0}
    实际：
      _send_combo([WIN, R])         steps += win+r
      sleep(0.35)
      _ensure_ascii_input()
      _type_unicode("notepad")      steps += type:notepad
      _tap_vk(ENTER)                steps += enter
      sleep(1.0)
      _ensure_ascii_input()
      _type_unicode(text)           steps += type:text
      返回 {dryRun:false, action:'macro.open_notepad_and_type', chars, steps, elapsedMs}
    异常 → InputError("E_MACRO_FAILED", f"macro open_notepad failed after {steps}: {err}", hint)
  macro_save_file():
    rate_limit + failsafe
    dry_run → {dryRun:true, steps:['ctrl+s'], elapsedMs:0}
    实际：_send_combo([CTRL, S])；异常 → E_MACRO_FAILED
2.2 协议（contract + cli）
  OPS / cmd.json op enum 增加：
    input.macro.open_notepad、input.macro.save
  cli.py：
    input.macro.open_notepad → input.macro_open_notepad_and_type(text)
    input.macro.save         → input.macro_save_file()
  InputError → ack error（E_MACRO_FAILED 原样透传）。
2.3 Node 工具（lib/index.js）
  vhcu_macro_open_notepad_and_type(text)：
    - 校验 text 非空/≤2000；
    - runInputAction('input.macro.open_notepad', {text}, {timeoutMs:20000})；
    - 成功后自动 captureFullFrame({max_width:1280})，markReadback()；
    - 返回 {ok, macro, dry_run, elapsed_ms, steps, frame_url, verify}；
    - 失败 → {ok:false, code: error.code ?? 'E_MACRO_FAILED', error, hint}。
  vhcu_macro_save_file()：同上（timeout 10s，max_width=1280）。
  两个 Description 均包含指定语句，并写明：需先 start_vision、失败 E_MACRO_FAILED、
  自动全屏校验、无需再单独回读。

3. 安全审计对照
====================================================================
  先看后做：runInputAction 统一检查 state.phase=running + supervisor ready，否则 E_STATE ✔
  宏内失败：Python 每步 catch → E_MACRO_FAILED（带 steps）✔
  执行后校验：Node 自动 vision.capture → 签名 frame_url + verify.ok ✔
  四角急停：宏入口 _failsafe()（光标在角落直接 E_DENIED，由 _input 映射）✔
  限流：宏算 1 次动作（Node 8/10s；Python 内部 12/5s 仍对子动作计数）✔
  回读门禁：宏成功自动抓帧即清除 pending，不阻塞下一次动作 ✔
  长度/键位：文本 ≤2000；宏内部只用固定键位（win+r / enter / ctrl+s）✔

====================================================================
5.1 重启
  ① 完全退出 DSH（托盘退出；任务管理器确认 Electron/python.exe 无残留）；
  ② 重新打开 DSH；新开会话；
  ③ 日志确认：dsh-vhcu: registered 11 tools。
5.2 测试指令（用户指定）
  发给模型：
  「用 vhcu_start_vision 开视觉；然后调用 vhcu_macro_open_notepad_and_type，
    输入「VHCU P7 宏测试」；告诉我 elapsed_ms、steps 和返回的 frame_url；
    再用 vhcu_get_vision_events 回读确认；最后 vhcu_stop_vision。」
  预期：
    - 一次工具调用完成 运行框→notepad→回车→等待→输入；
    - elapsed_ms 约 1500–3000ms（比逐步 click/type 多次往返快得多）；
    - frame_url 为签名全屏图，verify.ok=true；
    - 回读能看到记事本内容。
5.3 保存宏
  「用 vhcu_macro_save_file 保存当前文件；回读确认是否出现保存对话框。」
5.4 若宏失败
  - E_STATE：未先 start_vision。
  - E_MACRO_FAILED（消息含 steps）：Win+R 被拦截 / notepad 启动慢 / 焦点被抢；
    可延长等待需求或改单步操作；错误 hint 会提示先回读确认。
  - E_DENIED：鼠标在屏幕角落急停。
  - E_BUSY：限流，等待窗口结束。
  - verify.ok=false：宏成功但自动截图失败，补调 vhcu_get_full_frame。
