1. 全屏快照（消除盲区）
====================================================================
1.1 Python：Runner.capture_now()
  - 新增 self._snapshot_source：懒创建、独立于差分线程的 source（mss/fake）。
  - 抓一帧（不受 1fps 限制），写入 self._latest，返回
    {width,height,captureMs,capturedAt}。
  - /vhcu/frame 仍从 latest 取图，因此全屏快照立即可以被签名 URL 拉取。
  - daemon 新命令：vision.capture（无参数）→ 返回上述元数据。
1.2 Node：vhcu_get_full_frame(max_width?)
  - 要求视觉 running / supervisor ready，否则 E_STATE；
  - 发送 vision.capture（8s 超时），按返回的宽高生成整屏签名 URL：
    /vhcu/frame?x=0&y=0&w=<W>&h=<H>&maxw=<max_width>&exp=..&sig=..
  - 默认 maxw=1600（可 320..1920），返回：
    {ok, kind:'full_frame', width, height, max_width, capture_ms, frame_url, message}
  - render 自动追加 Markdown：`![全屏截图](frame_url)`。
  - 调用即清除 pending 回读状态（它本身就是回读）。

2. 新宏：滚轮 / 拖拽
====================================================================
2.1 Python input.py
  - scroll(amount)：
      int，0 → E_PROTO，|amount|>20 → E_PROTO；
      SendInput MOUSEEVENTF_WHEEL，mouseData = amount*120（WHEEL_DELTA）。
  - drag(x1,y1,x2,y2)：
      两端点 normalize_click 校验主屏边界；
      MOVE(start) → LEFTDOWN(start) → 12 步插值 MOVE → LEFTUP(end)；
      try/finally 保证按键一定释放。
  - 两者同样走 _rate_limit + _failsafe + dry-run。
2.2 Node 工具
  - vhcu_mouse_scroll(amount)：-20..20，正上负下；amount=0 在 Node 侧直接 E_PROTO。
  - vhcu_mouse_drag(x1,y1,x2,y2)：物理像素；拖拽后回读提示。
  - 返回体含 action/from/to/amount、dry_run、verify:{tool,after_ms:300}。

3. 强制回读（慢车道守护）
====================================================================
3.1 状态机
  - let pendingVerify = null;
  - 每个输入动作成功后 markActionPending(op) → {action, at}；
  - runInputAction 入口顺序：视觉检查 → requireReadback() → 限流 → 发送；
  - 未回读时抛 E_STATE：
      “上次动作（input.click）尚未回读确认：请先调用 vhcu_get_vision_events
       或 vhcu_get_full_frame”
  - vhcu_get_vision_events / vhcu_get_full_frame 成功即 markReadback()；
  - start/stop 也会清空 pending（重新开局不阻塞）。
3.2 描述
  五个输入工具 Description 都追加同一句：
  「每次执行 click/type/scroll/drag 后，必须在 500ms 内调用 vhcu_get_vision_events
    或 vhcu_get_full_frame 确认结果；如果没有确认，下一次动作将被拒绝（E_STATE）。」
3.3 为什么这样设计
  模型单步延迟远大于 500ms，真正可执行的是“动作后立刻回读、否则下一步被拒”；
  500ms 是回读前的等待建议（返回值 after_ms=300/400 与之一致），不是硬计时器。

5. 重启与验收（用户指定测试）
====================================================================
5.1 重启
  ① 完全退出 DSH（托盘退出 / 任务管理器确认 Electron 进程结束）；
  ② 重新打开 DSH；新开会话；
  ③ 日志确认：dsh-vhcu: registered 9 tools。
5.2 测试指令（直接发给模型）
  「用 vhcu_start_vision 开视觉；用 vhcu_get_full_frame 看清桌面，找到记事本图标并
    用 vhcu_mouse_click 打开；用 vhcu_type_text 输入“VHCU P6 测试”；用
    vhcu_mouse_scroll(3) 向上滚动；最后用 vhcu_get_full_frame 截全屏给我确认；
    结束调用 vhcu_stop_vision。」
  关键约束（模型必须遵守）：
    - 每次 click/type/scroll/drag 之后，先 get_vision_events 或 get_full_frame 回读；
    - 不回读就做下一个动作会被 E_STATE 拒绝。
5.3 失败排查
  - E_STATE “视觉未运行”：先 start_vision。
  - E_STATE “尚未回读确认”：调用 get_vision_events / get_full_frame 后重试。
  - E_DENIED：鼠标在屏幕四角（人工急停），移开。
  - E_PROTO：amount=0/越界、拖拽坐标越界、键名不支持。
  - E_BUSY：限流（Node 8/10s + Python 12/5s）。
  - 全屏图 409：视觉已停止，daemon 退出；重新 start。
