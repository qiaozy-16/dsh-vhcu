====================================================================
0. 结论（先看这 5 条）
====================================================================
C1. 新增硬上限 MAX_SEGMENT_SEC=4.0：
    语音缓冲累计到 4 秒，无论 VAD 当前是否静音，立即切片转写并清空。
C2. 静音判定 SILENCE_SEC 从 0.8 降到 0.4 秒，句子切分更灵敏。
C3. 效果：快速连续解说也会每约 4 秒产出一条短字幕，
    不再一次弹出几千字。
C4. [H] Hear 列表自动跟随最新一行；用户向上翻阅时不强行拉回。
C5. 测试：Node 46/46、Python 61/61；
    standalone 脚本同步 0.4s/4s 参数。

1. Python（vision/vhcu_daemon/hear.py）
====================================================================
1.1 常量
      SILENCE_SEC = 0.4       # 原 0.8
      MIN_SPEECH_SEC = 0.3
      MAX_SEGMENT_SEC = 4.0   # 新增
      PREROLL_FRAMES = 10     # 0.3s
1.2 新增纯函数
      def should_force_cut(frames):
          return bool(frames) and len(frames)*30ms >= 4.0s
1.3 采集循环
      每帧处理完 voiced/silence/preroll 后：
        if speech and should_force_cut(speech):
            print("[hear] segment forced at 4.0s (frames=..., voiced=...)")
            self._flush_segment(model, np, speech, speech_frames)
            speech = []
            speech_frames = 0
            silence_frames = 0
      - 强制切片不受 0.4s 静音条件限制；
      - 仍受 MIN_SPEECH_SEC=0.3 保护（当前缓冲必然 >=4s，不会误触）；
      - 每段最多约 4.0~4.3s（含 0.3s 预录），内存有界。
1.4 原有静音切片
      静音累计 >=0.4s 且 voiced >=0.3s → 切片。
1.5 standalone
      vision/test_hear_standalone.py 同步：
        SILENCE_SEC=0.4, MAX_SEGMENT_SEC=4.0
      循环内相同强制切片 + 日志，方便终端先验收字幕节奏。

6. 已知边界
====================================================================
R1. 4s 是硬切割：句子可能被从中间切开，字幕会更碎但更实时。
R2. 切片与转写是串行：转写约 1-2s 期间可能少采几帧，属伪流式。
R3. 0.4s 静音对嘈杂环境可能过于灵敏，后续可做成可配置。
R4. UI 自动滚动只在接近底部时触发，用户回看历史不会被拉走。
R5. 真实长视频节奏需重启后播放确认。
