1. Python（vision/vhcu_daemon/hear.py）
====================================================================
1.1 常量
      AMBIENT_RMS_THRESHOLD = 0.01
1.2 compute_rms(frames, np)
      samples = int16 / 32768.0
      rms = sqrt(mean(samples^2))
      - 空列表 → 0.0
      - 静音帧 → 0.0
      - 12000 振幅 → 约 0.366
1.3 _flush_segment
      rms = compute_rms(frames, np)
      duration_ms = len(frames) * 30
      emit_ambient(reason):
          if rms < 0.01: return
          self._emit("hear.audio",
              ts=now, rms=round(rms,4),
              duration=round(duration_ms/1000,2),
              durationMs=duration_ms,
              reason=reason)
      触发位置：
        - transcribe 异常 → reason="transcribe-error"
        - should_discard_transcript(text) → reason="filtered"
        - dedupe 后为空 → reason="filtered"
      成功转出文本 → 只发 hear.text，不发 ambient。
      低于阈值（真正静音）→ 什么也不发。
1.4 事件契约
      event.json enum 增加 hear.audio；
      oneOf 要求 rms 字段。
1.5 说明
      RMS 计算在原始 captured frames 上（不含 0.2s padding），
      与 duration 语义一致。

2. Node（lib/index.js）
====================================================================
2.1 attachSupervisor 新增 hear.audio：
      rms = Number(frame.rms)
      note('hear',
           `🎵 环境音/纯音乐 (音量: ${rms.toFixed(2)})`,
           {audio:true, rms, durationMs, reason, source:'loopback'},
           'info')
      若 hear 状态不是 listening，顺手锁定为 listening（同 hear.text 的
      状态自愈逻辑）。
2.2 ring
      以 kind:"hear" 存储，audio:true；
      因此复用 Hear tab、SSE、vhcu_get_hear_events，无需新 tab。
2.3 vhcu_get_hear_events

        kind: entry.audio ? "hear.audio" : "hear"
        audio: boolean
        rms: number|null

      工具描述补充：纯音乐/环境音返回 kind=hear.audio。

7. 已知边界
====================================================================
R1. RMS 是整段平均值，不能区分“音乐”与“环境噪声”；只表示有能量。
R2. 阈值 0.01 是经验值；极轻背景音乐可能低于阈值而不报。
R3. 环境音事件不更新 P14 空闲 watchdog 的 hear 活动时间（按“无转写文本”
    仍可能 5 分钟后自动休眠）。
R4. 环境音不参与 P15 多模态融合，只进 [H] 与 hear 工具。
R5. 真实纯音乐视频的 RMS/切段节奏需重启后人工验证。
