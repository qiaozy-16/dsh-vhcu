C1. Bug1 边缘漏字：
    - 切片音频头尾各补 0.2s Padding（PADDING_SEC=0.2，7 帧=210ms）；

    - 保留原有 0.3s 预录，_flush_segment 统一 pad 后送 whisper；

    - Node 收到 hear.text 即强制 state.hear=listening/running，pushStatus；

    - 即使 hear.status 丢失/竞态，只要有字幕，UI 必然绿灯。
C3. 测试：Node 46/46、Python 62/62；
    新增 padding 长度/头尾静音/空输入、0.6s 常量断言。

1. Bug1：边缘漏字
====================================================================
1.1 常量（vision/vhcu_daemon/hear.py）
      SILENCE_SEC = 0.6       # 原 0.4
      PADDING_SEC = 0.2
      PADDING_FRAMES = ceil(0.2*1000/30) = 7   # 210ms
      MAX_SEGMENT_SEC = 4.0   # 不变
1.2 新增 pad_audio()
      _SILENCE_FRAME = b"\x00\x00" * 480
      def pad_audio(frames, head=PADDING_FRAMES, tail=PADDING_FRAMES):
          return [silence]*head + frames + [silence]*tail
      - 头：在已有 0.3s 预录之外再补 0.2s 安全边距；
      - 尾：补 0.2s，避免 whisper 在 4s 强制切点吞掉最后一个音；
      - 空帧直接返回空。
1.3 _flush_segment
      padded = pad_audio(frames)
      audio = frombuffer(padded)
      print("[hear] transcribe segment: captured=...ms padded=...ms
             (+0.2s head/tail)")
      model.transcribe(audio, ...)
      - 原始采集不变，只在送给模型前补边；
      - 自然静音切点本来已带 0.6s 尾部静音，再加 0.2s 更稳；
      - 4s 强制切点也获得尾部 0.2s，降低边界吞字概率。
1.4 静音判定
      silence_frames*30ms >= 0.6s 才切；语音段最少 0.3s 不变。
      与 4s 强制切片共同工作。
1.5 standalone
      test_hear_standalone.py 同步 SILENCE_SEC=0.6、PADDING 0.2，
      transcribe 前做同样 pad，并打印 captured/padded。

2. Bug2：UI 状态不同步
====================================================================
2.1 Node（lib/index.js）
    hear.text 分支开头：
      if (state.hear.state !== 'listening' || !state.hear.running) {
          state.hear = {..., state:'listening', running:true, lastError:null};
          pushStatus();
      }
      note('hear', text, ...)
    → 字幕是管线存活的直接证据，状态立刻变绿。
2.2 前端（lib/client.js）
    SSE event handler：
      if (entry.kind === 'hear') {
          setState(previous => {
              if (hear.state==='listening' && hear.running) return previous;
              return {...previous, hear:{...hear,state:'listening',
                      running:true,lastError:null}};
          });
      }
      setEvents(...)
    → 即使 hear.status 事件丢失/先于面板挂载，也会被字幕纠正。
2.3 效果
    - 顶部状态灯绿色；
    - 文案“正在监听系统声音”；
    - 按钮“关闭听觉”；
    - 不再出现“字幕疯狂刷新但状态未启动”的撕裂。

6. 已知边界
====================================================================
R1. Padding 是静音边距，不是重叠识别：极端连读仍可能丢半字，
    但 0.2s 头尾 + 0.6s 静音已明显降低概率。
R2. 4s 强制切仍可能截断句子，可后续做 0.2s 重叠窗口。
R3. 状态纠正依赖 hear.text 事件；若完全无字幕，仍以 hear.status 为准。
R4. 转写与采集串行，长视频可能丢少量帧（伪流式）。
R5. 真实长视频验收需重启后人工播放同一片段。
