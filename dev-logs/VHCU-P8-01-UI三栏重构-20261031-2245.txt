0. 结论（先看这 7 条）
====================================================================
C1. 侧边栏仍然只有一个 Tab（id 不变 vhcu:monitor），标题由「VHCU 视觉」改为 **VHCU**；
    面板内部重构为三个数据 Tab：[V] Vision、[A] Action、[H] Hear。
C2. 数据面严格分流：SSE 的 `event:` 帧只允许 kind=vision|action|hear；
    internal status/error/daemon 只进内存环，不再作为数据事件推送；hello/补发也按三种 kind 过滤。
C3. 每条数据都有毫秒级 ts（Date.now()）。Vision 事件含 roiCount/diffMs/screen/rois[].frame_url；
    Action 事件含 action/ok/durationMs/params/error。
C4. Vision Tab：时间戳、ROI 数、diffMs、屏幕尺寸、坐标、每个 ROI 的签名缩略图（≤3 张）。
    Action Tab：时间戳、动作名、参数摘要、耗时 ms、成功/失败。
    Hear Tab：预留说明，当前只接受 kind=hear 契约。
C5. 右上角 ⚙ 悬浮层：调试模式（显示原始 JSON）、输入法切换（Ctrl+Space / Shift / 不切换）、
    宏管理（打开记事本 / 保存文件）；保存走 POST /vhcu/settings，并传给 Python 的 input.type/宏。
C6. 新增 /vhcu/settings GET/POST；settings 随 snapshot/status 下发；宏被禁用时工具返回 E_DENIED。
C7. 测试：Node 32/32、Python 39/39。新增：SSE kind/ts 断言、action 事件字段断言、
    5 条路由、设置 GET/POST、客户端三 Tab/⚙/标题 VHCU 静态结构。

1. 前端结构（lib/client.js）
====================================================================
1.1 单 Tab 注册
  sidebar.registerTab({
    id: 'vhcu:monitor',
    title: 'VHCU',                    ← 原「VHCU 视觉」
    description: '视觉/动作/听觉三栏监控、设置与实时事件流',
    order: 120, single: true,
    component: () => h(Panel),
  })
  仍然只有这一次 registerTab 调用；没有任何新 Tab。

1.2 面板布局
  header：状态灯 + VHCU + phase + 开启/关闭视觉 + ⚙
  meta：源 / pid / 帧 / 变化 / fps
  tabs：[V] Vision  count、[A] Action count、[H] Hear count
  list：按 activeTab 过滤 kind 后渲染
  footer：SSE 状态 + 上次错误/按需唤醒
  gear：透明 backdrop + 悬浮 panel（调试、IME、宏管理、保存/关闭）

1.3 Vision 行
  时间戳 · 「检测到画面变化 · N 个区域 · X ms」
  子行：ROI N · diffMs · 屏幕 · 坐标列表
  缩略图：rois[].frame_url → <img class=vhcu-thumb>，最多 3 张（10 分钟签名有效期）

1.4 Action 行
  时间戳 · 动作名 · 成功/失败 · durationMs
  子行：params 摘要（x/y、keys、amount、text、from/to）+ error
  debug 开启时追加原始 JSON。

1.5 Hear
  无数据时显示「Hear（预留）…」；有 kind=hear 事件时按通用行渲染。

2. 后端数据契约（lib/index.js）
====================================================================
2.1 kind 白名单
  const DATA_KINDS = new Set(['vision','action','hear']);
  note(kind,...)：
    - 所有记录都进 ring（供诊断）；
    - 只有 DATA_KINDS 命中时才写 `event: event` 帧；
    - status/error/daemon 记录不进入 SSE 数据面。
  /vhcu/state 的 events、SSE hello、Last-Event-ID 补发全部按 DATA_KINDS 过滤。

2.2 Vision 事件
  { id, ts:Date.now(), kind:'vision',
    text, roiCount, diffMs, screen:{width,height},
    rois:[{id,x,y,w,h,score,frame_url}] }
  frame_url 在广播时用现有 frameUrl() 生成（HMAC，TTL 10 分钟），前端可直接 <img>。

2.3 Action 事件
  recordAction(action,{detail,durationMs,ok,extra,error}) →
  { id, ts, kind:'action', action, ok, durationMs, params, text, error? }
  接入点：
    runInputAction(op,args,{action,detail,extra})：发送成功后/失败后各记一次；
      click / type_text / key_press / scroll / drag / macro_open_notepad / macro_save。
    captureFullFrame({__record:true})：full_frame 成功/失败记录。
  示例 text：`click · (812,410) · 12ms · ok`。
  drag 的 params 额外有 from/to（便于 UI 显示）。

2.4 设置
  let settings = { debug:false, imeShortcut:'ctrl+space',
                   macros:{open_notepad:true, save:true} };
  mergeSettings() 只接受白名单字段/取值；GET/POST /vhcu/settings；
  snapshot.settings 随 state/status/hello 下发；
  settings.imeShortcut 随 input.type/宏 args 传到 Python（type_text/macro 的 imeShortcut）；
  settings.macros.* 关闭时 Node 宏工具返回 E_DENIED（UI 可重新启用）。

2.5 Python IME 配置
  input.type_text(text, ime_shortcut='ctrl+space')
  macro_open_notepad_and_type(text, ime_shortcut='ctrl+space')
  _ensure_ascii_input(shortcut)：
    ctrl+space（默认）/ shift / none 三种；仍保留「复查一次」逻辑。
  cli.py 从 args.imeShortcut 读取并校验。

====================================================================
3. 接口
====================================================================
GET  /vhcu/state      → { ok, state, events }（events 仅三种 kind）
GET  /vhcu/events     → SSE：hello/status/event/心跳；event 仅三种 kind
POST /vhcu/control    → 启停/状态（不变）
GET  /vhcu/frame      → 签名 PNG（不变）
GET  /vhcu/settings   → { ok, settings }
POST /vhcu/settings   → JSON + x-vhcu:1；{settings:{debug,imeShortcut,macros}}
                        非法字段忽略/400；同源校验

5. 重启与验收
====================================================================
5.1 重启
  ① 完全退出 DSH（托盘退出；确认 Electron/python.exe 无残留）；
  ② 重新打开 DSH；侧边栏打开「VHCU」；
  ③ 日志：
      dsh-vhcu: mounted (routes /vhcu/state|events|control|frame|settings)
      dsh-vhcu: registered 11 tools
5.2 验收步骤
  1) 面板标题应为 VHCU，右上角有 ⚙；
  2) 三个标签 V Vision / A Action / H Hear 可切换，计数独立；
  3) 开启视觉 → Vision 出现事件与 ROI 缩略图；
  4) 让模型执行 click/宏 → Action 出现时间、动作、耗时、成功；
  5) Hear 显示预留说明；
  6) ⚙ 打开设置：改调试/输入法/宏开关 → 保存 → 重开设置确认保持；
     关掉某个宏后让模型调用该宏应返回 E_DENIED。
5.3 若 UI 没变化
  - 确认完全重启（client bundle 只在启动时加载）；
  - 日志若仍是旧 routes 文本，说明宿主加载的是旧 lib（检查 junction）；
  - 仍显示「VHCU 视觉」= client 未更新。
