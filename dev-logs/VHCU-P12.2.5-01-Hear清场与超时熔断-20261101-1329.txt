====================================================================
0. 结论（先看这 6 条）
====================================================================
C1. Hear-only 启动前强制清场：
    - 先停掉本插件 supervisor（SIGTERM/KILL）；
    - Windows 下执行 taskkill /F /IM python.exe，杀掉所有旧 Python 残留；
    - 设置 VHCU_KILL_ALL_PYTHON=0 可关闭全量强杀（应急）。
C2. hear.start 严格 10s 熔断：从发送命令开始计时，10s 内没收到
    hear.status=listening → E_TIMEOUT，state.hear=error，UI 红灯；
    超时会停止本次拉起的守护进程，绝不允许一直黄灯。
C3. 错误透传：捕获最近 30 行 Python stderr；加载报错/超时时把
    最后 8 行写入 state.hear.stderr，UI 控制条显示，同时 error 写入 lastError。
C4. 启动路径仍是 P12.2.4：绝对路径 + local_files_only=True + 无 download_root。
C5. 测试：Node 45/45、Python 56/56；真实超时/清场需人工验收（未跑 taskkill）。
C6. 每次点「开启听觉」都是全新 Python + 全新 hear 线程。

1. Node 修改（lib/index.js）
====================================================================
1.1 新增 import
      import { execFile } from 'node:child_process';
      import { promisify } from 'node:util';
      const execFileAsync = promisify(execFile);
      const HEAR_START_TIMEOUT_MS = 10000;
      const daemonStderr = [];       // 最近 30 行
1.2 forceKillPythonResiduals(reason)
      - supervisor.stop(reason)（自有守护进程）
      - daemonRunning=false, pid/port=null
      - 等 200ms
      - Windows 且 VHCU_KILL_ALL_PYTHON!=='0':
          execFile('taskkill', ['/F','/IM','python.exe'], timeout 5s)
          成功/失败都只记日志（没有 python 时 exit code 非 0 属正常）
      注意：这是全量杀 python.exe，会误杀其他 Python 任务；
      如需保留，设置环境变量 VHCU_KILL_ALL_PYTHON=0。
1.3 doStartHear
      daemonStderr.length = 0
      if 视觉未运行: await forceKillPythonResiduals('hear-preclean')
      const deadline = Date.now() + 10000
      const sup = await ensureDaemonReady()    // 新进程
      result = await sup.send('hear.start', {timeoutMs:10000})
      更新 state.hear（含 message/offline/loadedPath/stderr）
      await waitForHearReady(deadline - Date.now())
      return snapshot()
1.4 waitForHearReady(timeoutMs)
      - 立即检查：listening → 成功；error → 抛 E_HEAR_FAILED
      - 每 100ms 轮询 state.hear
      - 超过 deadline → 抛 E_TIMEOUT:
          message: "Hear 启动超时（10s）：未收到 listening"
          hint: 最近 8 行 daemon stderr
1.5 错误处理
      catch:
        state.hear.state='error'
        lastError=error.message
        stderr=最近 8 行（或原 stderr）
        若视觉未开：停止本次守护进程，清 pid/port/daemonRunning
        pushStatus(); throw（control 路由返回 409 + error.code）
1.6 stderr 缓冲
      attachSupervisor: sup.on('stderr', line => {
        daemonStderr.push(String(line).trim());
        if (>30) shift;
      })
      hear.status error → state.hear.stderr = 最近 8 行。

7. 已知边界（重要）
====================================================================
R1. taskkill /F /IM python.exe 是**全局强杀**：会杀掉本机所有 Python
    （包括其他脚本/记忆服务）。这是用户明确要求的“极致清场”。
    需要保留时设置 VHCU_KILL_ALL_PYTHON=0，插件只杀自己的 supervisor。
R2. 10s 是硬上限：模型首次冷加载超过 10s 会被判超时并停守护进程；
    本地模型实测 1s，正常不会触发。
R3. 停止视觉仍会停止共享守护进程与 Hear。
R4. 超时/错误后 UI 红灯，不会自动重试；用户可再次点开启。
R5. 真实音频转写仍需播放系统声音验证。
